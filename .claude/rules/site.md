# Showcase page
Desktop only: cloud threads don't load path rules. CLAUDE.md repeats the lines that must hold everywhere.
- The page is plain files: `site/index.html`, `theme.js`, `app.js`, `app.css`, `favicon.svg`. No build step; edit, then reload `make preview`.
- `site/roadmap.json` is generated by `roadmap build`. Never edit it by hand; CI fails when it's stale. Page text comes from the repo files and `showcase.toml`. Progress comes from ticks and the ledger, never hard-coded.
- Copied unchanged, never edited here: `site/ds/` (from the Dukecodes Design System artifact; `site/ds.lock.json` names it, its version and each file's source), `site/vendor/` (React, from the npm tarballs in the lock), `scripts/check_site.py` and `scripts/ds_tokens.py` (from `dukecodes-project-template`), and the `designSystem` pairs in `site/contrast.json` (from the design system's QA kit).
- To take a design-system release: copy each file the lock lists from the artifact, run `make site-tokens`, then `uv run python scripts/check_site.py --relock`, set `designSystem.version` and `synced` in the lock, and run `make check`. Relock only after copying a release, never to silence a hash failure.
- Page CSS goes in `site/app.css`: `rm-` prefix, design-system tokens for every color. A rule that patches a `dk-` class is marked `DS fix` and gets a row in `docs/design-system-fixes.md`.
- A new text color needs a pair in `site/contrast.json` (WCAG AA in both themes), or the page check fails.
- The CSP and Trusted Types allow no inline script or style and no string-to-HTML calls. `app.js` uses `React.createElement` only: no innerHTML, dangerouslySetInnerHTML, eval, string timers, `setAttribute` for `style` or `on…`, and no RegExp built from data. `fetch` takes a relative string literal only.
- Links from data are https or `#token` only. Never publish real IPs, hostnames, MACs or tailnet names: `roadmap check` scans every file in `site/`.
